## Overview

This project is an **ML-powered smart web scraper** designed to handle **pagination vs infinite scroll** detection automatically. It combines **rule-based fallbacks** with a **configurable machine learning analyzer** to adapt to different e-commerce sites like **Tokopedia** and **Amazon**.

---

## Modules

### 1. `analyzer.py`

- **Core ML Analyzer**: Extracts page features (buttons, lazy-loading, DOM growth, text patterns).
    
- Supports **rule-based fallback** when ML confidence is low.
    
- Features loaded dynamically from **YAML config**.
    
- Collects training samples and saves to versioned CSVs.
    
- Trains a `RandomForestClassifier` with **TF-IDF text features**.
    
- Implements **model versioning** (`pagination_model_vYYYYMMDD_HHMMSS.pkl`).
    

---

### 2. `scraper.py`

- Orchestrates the scraping process.
    
- Uses the analyzer to detect pagination type (`pagination`, `infinite_scroll`, `last_page`).
    
- Integrates **human-like scrolling** via `RandomUtils`.
    
- Calls `collect_training_data()` after each page or scroll round.
    
- Saves scraped products using `DataStorage`.
    

---

### 3. `parser.py`

- Parses product details from search result pages.
    
- All CSS/XPath selectors are defined in **`config/parsers.yaml`**, making parsing **site-agnostic**.
    
- Extracted fields: `title`, `price`, `shop`, `rating`, `review_count`.
    

---

### 4. `utils.py`

- Provides **human-like scrolling simulation** (`RandomUtils.human_like_scroll`).
    
- Randomized delays to mimic user behavior.
    
- Supports incremental training feature collection (`scroll_round`, `new_items_loaded`).
    

---

### 5. `browser.py`

- Manages Selenium WebDriver (headless Chrome).
    
- Handles navigation, session management, error recovery.
    

---

### 6. `storage.py`

- Handles saving extracted product data into structured formats (CSV/JSON/DB).
    
- Used by `scraper.py`.
    

---

## Workflow

1. **Navigate** to a search results page.
    
2. **Analyze page structure** → predict pagination type.
    
3. **Scrape products** via YAML-driven parser.
    
4. **Collect training data** at each step (saved into `training_data.csv` + versioned copy).
    
5. **Act on pagination**:
    
    - Click "Next" button for traditional pagination.
        
    - Perform human-like scroll for infinite scroll.
        
    - Stop if last page detected.
        
6. **Incremental training** can be scheduled periodically.
    
7. **Model + training data** are saved with version numbers for reproducibility.
    

---

## Versioning Strategy

- **Models**:  
    Saved in `models/pagination_model_vYYYYMMDD_HHMMSS.pkl`  
    Symlink / copy to `pagination_model.pkl` for "latest".
    
- **Training Data**:  
    Always saved into:
    
    - `models/training_data.csv` (rolling log)
        
    - `models/training_data_vYYYYMMDD.csv` (daily snapshot)
